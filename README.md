# 在你身边 - 主动消息插件（改造版 v4.1.0）

基于 Iris_祈鸢 的原版插件改造。

## 改造内容

### 1. 白名单 → 黑名单
- 原版：只有白名单中的用户才会收到主动消息
- 改造：默认所有用户都会收到主动消息，黑名单中的用户被排除
- 修复：黑名单匹配已统一转为字符串比较，不再有类型不匹配问题

### 2. 群聊主动消息开关（新增）
- 新增 `group_chat_config.enable_group_active_message`，**默认关闭**
- 关闭时所有群聊都不会收到主动消息，也不会被追踪或创建延迟任务
- 通过检测 session_key 中的 "group" 关键词自动识别群聊

### 3. 概率触发
- 新增 `trigger_probability` 配置（0-100%）
- 满足空闲时间后，按概率决定是否发送。未命中时重置计时器等下一轮

### 4. 智能话题策略
- 新增 `new_topic_probability` 配置（0-100%）
- 触发时按概率选择：**续聊上下文** 或 **开启新话题**
- 建议设为 60% 以上（用户不回了通常不想继续旧话题）

### 5. 合并短期/长期
- 原版有两套独立的后台任务（短期跟进 + 长期维系），提示词不同但逻辑重叠
- 改造为统一的空闲检测系统，一个后台任务搞定

### 6. 修复追发 Bug
- **修复重复代码bug**：原版 except 块中有重复的任务创建代码
- **统一冷却时间**：所有主动消息（包括 delayed_followup）都使用 `idle_trigger_min_minutes` 作为最小间隔
- **代码决定时间**：LLM 只判断是否跟进并生成内容，不能返回或指定发送时间；所有等待时间均由代码在配置范围内重新随机
- **单一待跟进优先**：已有延迟跟进时，空闲检测不会再创建一条竞争消息

### 7. 与角色作息插件联动
- 自动读取角色作息插件公开的实时状态，不复制或猜测每日作息
- 只有作息状态为“在线”时才允许生成和发送主动消息
- 即将离开、暂时离开、睡觉和回归处理中均不发送
- 生成前、真正发送前以及拆分消息逐段发送前都会重新检查，防止生成期间跨入睡眠时段
- 离线时到期的旧跟进直接放弃，不会在起床后集中补发；恢复在线后重新随机等待时间
- 作息插件未运行时，继续使用本插件的固定免打扰时间
- WebUI 中原有的“启用免打扰”已明确为“使用免打扰时间”；作息插件正常运行时可以关闭

### 8. 修复插件卸载后仍发消息的幽灵任务 Bug
- **根本原因**：原版 `stop()` 未取消 `scheduled_tasks` 中的延迟任务，asyncio 协程在事件循环中持续存活
- **修复**：
  - `stop()` 时设置 `_stopped` 标志并取消所有延迟任务
  - 所有发送操作（后台检查、消息生成、延迟任务）在执行前检查 `_stopped` 标志
  - 即使 asyncio cancel 失败，`_stopped` 标志也能阻止实际发送

## 配置说明

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `trigger_probability` | 空闲触发后的发送概率(%) | 80 |
| `new_topic_probability` | 选择新话题的概率(%) | 60 |
| `idle_trigger_min_minutes` | 最短空闲触发时间(分钟)，同时也是所有主动消息的最小冷却间隔 | 30 |
| `idle_trigger_max_minutes` | 最长空闲触发时间(分钟) | 80 |
| `max_consecutive_messages` | 最大连续追发次数 | 3 |
| `enable_group_active_message` | 允许群聊主动消息 | **false** |
| `quiet_hours_enabled` | 使用固定免打扰时间；作息插件正常联动时可关闭 | true |
| `blacklist_enabled` | 是否启用黑名单 | false |
| `blacklist_users` | 黑名单QQ号列表 | [] |

## 升级注意

- 原版的 `whitelist_config` 已改为 `blacklist_config`
- 原版的 `proactive_initiation_config`（长期主动消息）已并入 `idle_check_config`
- state.json 中的 `proactive_counters` 字段不再使用（自动忽略，无需手动清理）
